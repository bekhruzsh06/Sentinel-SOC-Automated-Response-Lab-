### Step 1: Set Up Your Azure Environment

- Go to `azure.microsoft.com` and click **Start free**. Students can use **Azure for Students** instead, which gives free credit without a credit card.
- Complete the registration (the free trial requires a Microsoft account and a credit card for identity verification, but you won't be charged unless you manually upgrade).

![Azure portal home](../images/01-setup/01-azure-portal-home.png)


### Step 2: Deploy the Honeypot Virtual Machine

We are going to deploy a Windows virtual machine and intentionally expose it to the internet to attract automated threat actors.

1. In the top search bar, type **Virtual Machines** and select it.

![Search for Virtual Machines](../images/01-setup/02-search-virtual-machines.png)

2. Click **Create** > **Azure virtual machine**.

3. Configure the **Basics** tab:
    - **Subscription:** Azure subscription 1 (or your free tier).
    - **Resource group:** Click "Create new" and name it `SOC-Lab-RG`.
    - **Virtual machine name:** `soc-honeypot-vm`
    - **Region:** Choose a region close to you. This lab used **South Africa North**.
    - **Image:** Select **Windows 10 Pro** or **Windows Server 2022 Datacenter**.
    - **Size:** Select **Standard_B1s** or **Standard_B2s** (these are very cheap/free tier eligible).
    - **Administrator account:** Create a username and a strong password. You will use this to log in.
    - **Public inbound ports:** Select **Allow selected ports**.
    - **Select inbound ports:** Check **RDP (3389)**. This is crucial: leaving this open to the internet is what will attract the attackers.

4. Click **Review + create**, then click **Create**. Wait a few minutes for the deployment to finish.

![VM deployment in progress](../images/01-setup/03-vm-deployment-in-progress.png)

![VM deployment complete](../images/01-setup/04-vm-deployment-complete.png)


### Step 3: Lower the VM's Internal Defences

To make sure we capture all inbound connection attempts in our logs without the local Windows OS blocking them silently, we will disable the internal Windows Firewall.

1. Once the VM is deployed, go to the VM's **Connect** page and download the RDP connection file.

![VM Connect page](../images/01-setup/05-rdp-connect-page.png)

2. Open the file with **Remote Desktop Connection** on your local computer and log in using the credentials you created in Step 2.

![RDP security warning](../images/01-setup/06-rdp-security-warning.png)

![RDP credentials prompt](../images/01-setup/07-rdp-credentials.png)

![RDP certificate warning](../images/01-setup/08-rdp-certificate-warning.png)

3. Once logged into the VM, click the Start menu, type **PowerShell**, right-click it, and select **Run as Administrator**.

![Run PowerShell as administrator](../images/01-setup/09-powershell-run-as-admin.png)

4. Run the following command to disable the Domain, Private and Public firewall profiles:

```powershell
Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled False
```

![Disable Windows Firewall](../images/01-setup/10-disable-windows-firewall.png)

5. Leave the VM running. Within an hour, automated scanners from around the world will find the open RDP port and start trying to brute-force the password.


### Step 4: Create a Log Analytics Workspace (LAW)

This is the database that will store all the logs generated by the honeypot VM.

1. Go back to the Azure Portal.
2. In the search bar, type **Log Analytics workspaces** and select it.

![Search for Log Analytics workspaces](../images/01-setup/11-search-log-analytics.png)

3. Click **Create**.

![Create Log Analytics workspace](../images/01-setup/12-law-create.png)

4. Select your `SOC-Lab-RG` resource group.
5. Name the workspace (e.g. `SOC-Lab-LAW`) and select the same region as your VM.

![LAW review and create](../images/01-setup/13-law-review-create.png)

6. Click **Review + Create**, then **Create**.


### Step 5: Enable Microsoft Sentinel

Now we turn that database into a full Security Information and Event Management (SIEM) system.

1. In the Azure search bar, type **Microsoft Sentinel** and select it.

![Search for Microsoft Sentinel](../images/01-setup/14-search-sentinel.png)

2. Click **Create**.

![Create Microsoft Sentinel](../images/01-setup/15-sentinel-create.png)

3. Select the workspace you just created (`SOC-Lab-LAW`) and click **Add**.

![Add Sentinel to the workspace](../images/01-setup/16-sentinel-add-workspace.png)

4. You now have a 31-day free trial of Sentinel activated on this workspace.

![Sentinel enabled](../images/01-setup/17-sentinel-enabled.png)


### Step 6: Connect the VM Logs to Sentinel

Finally, we need to make the VM send its Windows Security Event logs (specifically failed logins) into Sentinel.

1. Inside your new Microsoft Sentinel workspace, scroll down the left menu to **Configuration** and click **Data connectors**.

![Data connectors menu](../images/01-setup/18-data-connectors-menu.png)

2. Go to the **Content Hub**, search for **Windows Security Events** and install the solution.

![Content Hub link](../images/01-setup/19-content-hub-link.png)

![Install Windows Security Events](../images/01-setup/20-content-hub-windows-security-events.png)

3. Back on the Data connectors page, select **Windows Security Events via AMA** and click **Open connector page**.

![Open connector page](../images/01-setup/21-open-connector-page.png)

4. Click **Create data collection rule**.

![Create data collection rule](../images/01-setup/22-create-data-collection-rule.png)

5. Name the rule (e.g. `Honeypot-Security-Logs`), add the VM from our resource group, and choose which events to collect.

![DCR review and create](../images/01-setup/23-dcr-review-create.png)
